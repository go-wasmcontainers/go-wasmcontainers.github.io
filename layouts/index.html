Why go-wasmcontainers

A lab should be a web page, not a virtual machine.

Teaching containers usually means provisioning a Linux machine per learner. WASI modules need no kernel, so the same engine that runs natively can, in the plan, run in a browser worker.

🐳

The Docker CLI, unchanged

The engine answers the Docker Engine API (v1.47 is the version its reference is read from) on /var/run/docker.sock. Learners type the docker commands they will type at work.

🧊

WASI images

An image is an OCI image whose platform is os=wasip1, arch=wasm; the layer is a module. Images are meant to be apt-like, built from pkgx wasip1 bottles — a target go-pkgx is gaining now.

⚙️

wazero executor

Containers run in wazero, a pure-Go WebAssembly runtime: no cgo, no kernel namespaces, one static binary.

🌐

Planned: the browser

The playground is a terminal running docker against WASI containers, entirely in a page. It has not been started; it depends on the executor running in a browser worker.
